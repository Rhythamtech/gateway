# Backend audit · 2026-11-22

Current scope covers the PostgreSQL gateway, its three inference interfaces, credit accounting and dashboard authentication. The findings below are open and confirmed by source inspection. Checks used an isolated SQLite database. The general suite passed 148 tests and skipped five PostgreSQL integration tests. Live upstream behavior and deployment performance were outside this verification.

| Priority | Finding and impact | Minimal fix and acceptance check |
|---|---|---|
| P1 | **Responses streaming can announce success after upstream failure.** The event loop ignores error-only chunks and falls through on clean EOF. It then emits a completed event even though the observer tracks upstream errors and missing termination. Clients can accept a partial answer as final. See `backend/gateway/responses/controller.py:78` and `backend/gateway/execution.py:226`. | Gate successful completion on the observer's terminal and failure flags. Emit a failed terminal event otherwise. Cover an upstream error followed by a terminator and EOF after a partial delta. Neither should produce success. |
| P2 | **Successful final Responses objects lose the answer text.** The adapter forwards each text delta but hardcodes an empty string in the completed message. Consumers using the final object receive empty output. See `backend/gateway/responses/controller.py:98` and line 127. | Accumulate text fragments and join them in the final message. Verify two deltas produce the same text in the completed object. |
| P2 | **Provider error bodies cross the credential boundary.** The transport reads the entire error body and forwards its first 2,000 decoded characters through the public error envelope. Provider diagnostics can contain private configuration or account details. Streaming requests also buffer the entire error before truncation. See `backend/gateway/providers/service.py:778` and `backend/main.py:245`. | Close the error response and expose a stable gateway message with the existing status and code. Verify a synthetic private diagnostic stays out of the client response and streamed errors require no full-body read. |
| P2 | **Anthropic stop sequences disappear on OpenAI routes.** The Messages DTO accepts extra fields. The converter copies a field named `stop`, while the incoming Anthropic setting is `stop_sequences`. A valid stopping condition is silently lost and generation can run longer than intended. See `backend/gateway/chat/models.py:111` and the reverse mapping at line 233. | Map incoming stop sequences to the OpenAI stop field. Verify the dispatched body for a Messages request routed to an OpenAI provider. |
| P2 | **Disabled accounts can renew credentials.** Refresh verifies the JWT and issues a new pair without checking the user's current state. Protected routes still reject an inactive user, but a refresh credential kept alive during suspension becomes usable upon reactivation. See `backend/auth/service.py:116` and `backend/dependencies.py:28`. | Apply the existing active-user check at refresh. Verify disabled and deleted users receive 401 and active users can still renew. |
| P2 | **Dispatch reloads provider configuration after admission.** Attempt capture resolves the runtime provider, then transport resolves its mutable alias again. This adds a database lookup per inference and permits configuration changes between payload conversion, reservation and dispatch. See `backend/traces/capture.py:141`, `backend/gateway/execution.py:153` and `backend/gateway/providers/service.py:752`. | Pass the admitted runtime provider into transport. Verify dispatch uses the same provider configuration and performs no second alias query. |

Coverage was deepest on admission, protocol conversion, streaming, upstream errors and authentication. Administrative CRUD, analytics, migrations and concurrent settlement received partial coverage through the test suite. No production latency measurement or independent security certification is implied.

## Resolution · 2026-11-22

Fixed all six findings. Responses now distinguish completed streams from provider errors or premature EOF, and final output includes the streamed text. Dispatch uses the admitted provider configuration and closes failed HTTP responses without reading their bodies. Messages preserves Anthropic stop sequences on OpenAI routes, and refresh requires an active account. All 161 backend tests passed with the five PostgreSQL integration tests enabled against a disposable local database.
